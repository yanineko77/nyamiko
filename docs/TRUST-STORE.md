# Nyamiko: хранилище сертификатов телевизора

## Проблема

Прошивки 2018 года принесли с собой ~187 корневых сертификатов. За прошедшие
годы часть сайтов перешла на новые удостоверяющие центры, которых там просто
нет: VK подписан **SSL.com**, VK Видео — **HARICA**, госуслуги — российским
корневым сертификатом Минцифры.

Симптомы:

```sh
curl -k https://vk.com/          # 302 - сеть в порядке
curl    https://vk.com/          # 000 - проверка не проходит
openssl s_client -connect vk.com:443 </dev/null | grep Verify
# verify error:num=19:self signed certificate in certificate chain
```

## Решение

Корневой раздел смонтирован только для чтения (`overlay ... ro`), поэтому
системный каталог `/etc/ssl/certs` подменяется bind-монтированием подготовленной
копии:

1. исходный бандл сохраняется как `.../ca/orig.crt` (до первой подмены!);
2. к нему добавляются **только отсутствующие** корни — сравнение по отпечаткам
   SHA-256 (получилось +76, итого 263 сертификата);
3. готовится каталог: копия системного + хешированные ссылки
   (`openssl x509 -hash -noout` → `<hash>.0`). Нужны **обе формы**: сборный
   `ca-certificates.crt` читают curl и часть библиотек, а каталог — Chromium и
   приложения телевизора;
4. `mount --bind <каталог> /etc/ssl/certs`;
5. при загрузке всё это повторяет хук
   `/var/lib/webosbrew/init.d/55-ca-extra` (номер меньше 60, чтобы успеть до
   туннеля).

## Как добавить свой корень

```sh
cat my-ca.pem >> /media/internal/tv-tunnel/ca/extra/local.pem
sh /var/lib/webosbrew/init.d/55-ca-extra      # пересобрать и перемонтировать
curl -s -o /dev/null -w '%{http_code}\n' https://сайт/
```

Для хешированных ссылок новых сертификатов используйте
`tools/ca-add-links.sh` (скрипт из этого репозитория) или повторите шаги 3–4
вручную. Проверка: `openssl s_client ... | grep "Verify return code"` должно быть
`0 (ok)`.

## Проверено

`vk.com` 302, `vkvideo.ru` 302, `youtube.com` 200, `openssl` для обоих сайтов
`Verify return code: 0 (ok)`. Туннель и маршрутизация при этом не затрагиваются.
